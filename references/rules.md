# 判定规则详表

## 规则来源

本文档为 `doc-reorg` Skill 的判定规则细则，对应 SKILL.md 中的 R1–R8。

## 判定优先级（顺序判定，命中即止）

**R8 > R1 > R2 > R6 > R7 > R5 > R3**

先查标题文件碎片（R8，最快），再查正文二进制（R1），再查数据库 dump（R2），
再查结构化文档类型（R6），再查大文档（R7），再查有用性（R5），最后处理附件（R3）。

## R8 文件碎片 → 不搬（新增）

- 判定方式：标题含压缩包/视频文件扩展名
- 匹配扩展名列表：`.7z`, `.rar`, `.zip`, `.tar`, `.gz`, `.bz2`, `.flv`, `.mp4`, `.avi`, `.mkv`, `.mov`, `.wmv`, `.exe`, `.iso`, `.dmg`, `.apk`
- 匹配规则：不区分大小写，标题末尾或含空格后出现扩展名即为命中
- 原因：用户上传的文件碎片（如 7z 分卷包、视频文件等）被语雀存储为独立文档，实质是二进制上传碎片，非文档内容
- 特点：判定最快（仅查标题字符串，无需读 body），排在规则链最前面

## R1 正文二进制 → 不搬（修正）

- 判定方式：文档正文无法解析成文本（二进制内容）
- **例外**：lake 格式文档即使 body 含不可读数据（如视频卡片、文件卡片嵌入），只要正文框架可解析（有 `<card>` 标签等结构），就不算二进制
- 注意：纯附件文档（正文是文字、挂附件）**要搬**，附件跟着正文走
- 一句话：看正文，不看附件；lake 卡片格式的二进制不做二进制

## R2 数据库 dump → 不搬

- 判定方式：文档内容是数据库 dump

## R3 附件 → 随正文搬

- 正文是文字的文档，其附件一并搬运
- 附件不独立成篇，跟随所属文档

## R4 格式零转换

- 源文档 `format` 字段的枚举值：`markdown` / `lake` / `html`（注意：**没有 sheet**）
- Sheet 不是 format，是文档 `type`（Doc/Sheet/Thread/Board/Table）
- 搬运时 `yuque_copy_doc` 的 `format` 参数传源文档 format 原值
- 不做 lake→markdown 之类的转换（会丢代码块、图片、表格格式）

## R6 结构化文档类型（type=Sheet/Board/Table）

- `copy_doc` 参数是 title/body 纯文本，传不了结构化正文（sheet 走 `body_sheet` JSON，table 走 `body_table`）
- 遇到 `type` 非 Doc 的文档：**标记「待老板裁决」**，不强行搬
- 判断依据：文档对象里的 `type` 字段，不是 format

## R7 Big Doc 拆分（新增）

- 触发条件：文档 body 长度 > 200KB（≈ 200,000 字节）
- 操作流程：
  1. 用 `yuque_export_doc` 或 API 获取文档完整内容
  2. 按章节标题拆分：
     - 识别 `#`/`##`/`###` 等 Markdown 标题
     - 识别中文编号标题（`一、` `二、` `第一章` `第1节` 等）
     - 识别 `##` 开头的 lake 卡片标题
  3. 每条拆分结果作为独立文档写入 B 库
  4. 标题格式：`{原文档名} - {章节名}`
- 注意事项：
  - 拆分后每篇文档的 `format` 保持源格式
  - 附件跟原文档走，不拆分到各章节
  - 纯文本不分章节的文档降级为整体搬运（不做硬拆分）
  - 拆分失败时整体搬运该文档

## R5 有用性范围（老板给定）

三种填法，任务开始时向老板确认：

| 方式 | 说明 | 特点 |
|---|---|---|
| 范围法 | 给主题/关键词清单，命中才搬 | 最严，AI 不会搬错 |
| 目录法 | A 库指定目录整片搬，其他跳过 | 最省事，不用逐篇判断 |
| **全扫法（默认）** | A 库全扫，非二进制/非dump/非文件碎片/非结构化文档的全搬 | 最宽，适合初始整理 |

## 拿不准处理

- R5 命中不了硬规则 → 打标"拿不准"，集中列一行给老板扫一眼，不搬
- 不猜，不自行扩大/缩小范围
