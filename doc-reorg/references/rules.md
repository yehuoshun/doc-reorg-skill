# 判定规则详表

## 规则来源

本文档为 `doc-reorg` Skill 的判定规则细则，对应 SKILL.md 中的 R1–R9。

> 本文件是规则的**唯一正文**；SKILL.md 只保留一行式速查表，细则一律以此为准。

## 判定优先级（顺序判定，命中即止）

**R1 > R2 > R8 > R6 > R5 > R7 > R3**

先查正文二进制（R1），再查数据库 dump（R2），再查无意义内容（R8），
再查结构化文档类型（R6），再查有用性（R5），再查大文档写入策略（R7），最后处理附件（R3）。

## R1 正文二进制 → 不搬

- 判定方式：按源 `format` 取对应 body 字段（`lake` → `body_lake`，`markdown` → `body`，`html` → `body_html`），检查是否纯二进制乱码。**禁止用 `body` 判 lake 文档**——`body` 会 strip `<card>` 标签，把合法附件文档误判为二进制
- **不搬**：可打印字符比例 < 50%（纯二进制乱码，如 7z 分卷包的 body 数据）
- **要搬**：即使可打印字符比例低，只要 body 包含 `<card` 标签（lake 卡片结构），就不算二进制
- 标题含 `.7z` / `.flv` / `.mp4` / `.zip` / `.rar` / `.w3x` / `.js` / `.gif` 等扩展名不能作为判断依据——必须是 lake 卡片（`<card>` 标签）才算有效文档
- 常见被误判但实际有效的文档类型：
  - 魔兽地图文件（`.w3x`）作为附件嵌入 lake 卡片
  - JavaScript 脚本（`.js`）作为附件嵌入 lake 卡片
  - 图片文件（`.gif` / `.png` / `.jpg`）作为附件嵌入 lake 卡片
  - 视频文件（`.mp4` / `.flv`）作为附件嵌入 lake 卡片
- 一句话：**看 body 内容，不看标题**。有 `<card>` 标签的就是有效 lake 文档，纯乱码无 card 标签的就是二进制碎片

## R2 数据库 dump → 不搬

- 判定方式：文档内容是数据库 dump

## R3 附件 → 随正文搬

- 正文是文字的文档，其附件一并搬运
- 附件不独立成篇，跟随所属文档

## R4 格式零转换

- 源文档 `format` 字段的枚举值：`markdown` / `lake` / `html`（注意：**没有 sheet**）
- Sheet 不是 format，是文档 `type`（Doc/Sheet/Thread/Board/Table）
- 搬运时 `yuque_create_doc` 的 `format` 参数传源文档 format 原值
- 不做 lake→markdown 之类的转换（会丢代码块、图片、表格格式）

### body 字段选择（重要）

`yuque_get_doc` 返回三个 body 字段，必须按 format 选择正确的字段：

| 源 format | 使用的 body 字段 | 说明 |
|---|---|---|
| `markdown` | `body` | 原生 markdown 文本 |
| `lake` | `body_lake` | **必须用 body_lake**，用 `body` 会丢失 card 标签（视频卡片、文件卡片）内的附件链接 |
| `html` | `body_html` | 原生 HTML |

**错误示例**：lake 格式文档用 `body` + `format=markdown` 搬运 → card 标签被 strip，附件链接变为 markdown 文本链接，指向源库 CDN 而非目标库，导致附件失效。

**正确做法**：`body_lake` + `format=lake` → card 标签保留，语雀自动处理 CDN 路径重定向。

## R6 结构化文档类型（type=Sheet/Board/Table）

- `copy_doc` 参数是 title/body 纯文本，传不了结构化正文（sheet 走 `body_sheet` JSON，table 走 `body_table`）
- 遇到 `type` 非 Doc 的文档：**标记「待老板裁决」**，不强行搬
- 判断依据：文档对象里的 `type` 字段，不是 format

## R7 Big Doc 拆分

- 触发条件：文档 body 长度 > 200KB（≈ 200,000 字节）
- ⚠️ 命令行长度限制先行：`yuque_create_doc` / `yuque_copy_doc` 把 body 作命令行参数，body > 50KB 就可能 `Argument list too long`，需改 `yuque_import_file`（body 写本地文件，命令只传路径，无长度限制）
- ✅ **format 全支持**：`yuque_import_file` 的 `format` 支持 `markdown` / `lake` / `html`（MCP `references/api/extended_api.md`），拆分后**按源 format 原值写入，不做格式转换**
  - ⚠️ 该工具调用侧内联 schema 描述只写了 "markdown / html"，是 MCP 侧的陈旧描述，**以 references 为准（lake 可用）**
- 操作流程：
  1. 用 `yuque_get_doc` 取完整正文（按 format 选 `body` / `body_lake` / `body_html`）；也可用 `yuque_export_doc`，但注意其默认把 body_html 转 markdown，markdown 文档可传 `raw_body=true` 保原样
  2. 按 **~200KB 段落**切分：在段落/空行边界处切，每段 ≤200KB，避免掐断句子；**lake 拆分点必须避开 `<card>` 块，不能把卡片拦腰切断**
  3. 每段写入本地文件 → `yuque_import_file` 导入，`format` 传源原值，`paths` 传目标目录（必填，1-5 条）
  4. 标题格式：`{原文档名} - 第 N 段`
- 注意事项：
  - 拆分后每篇文档的 `format` 保持源格式（含 lake）
  - 附件跟原文档走，不拆分到各段；lake 正文中的 `<card>` 整体留在所属段内，不切断
  - body ≤200KB 的不拆分，降级整体搬运
  - 拆分失败时整体搬运该文档

## R5 有用性范围（老板给定）

三种填法，任务开始时向老板确认：

| 方式 | 说明 | 特点 |
|---|---|---|
| 范围法 | 给主题/关键词清单，命中才搬 | 最严，AI 不会搬错 |
| 目录法 | A 库指定目录整片搬，其他跳过 | 最省事，不用逐篇判断 |
| **全扫法（默认）** | A 库全扫，非二进制/非dump/非结构化文档的全搬 | 最宽，适合初始整理 |

## R8 无意义内容（纯水文档）→ 不搬

- 判定方式：正文内容极短或仅含无意义字符，无法构成有效信息
- 优先级：R8 **在 R1、R2 之后，R6、R5、R7 之前**（即先检查 R1 二进制 / R2 数据库 dump，再检查 R8 无意义，再 R6/R5，最后 R7 写入策略）
- 不搬条件（满足任一即可）：
  - 正文长度 < 10 字符（去除空白后）
  - 正文仅含纯数字、标点、空白符、换行符等无意义字符
  - 正文是 Java 对象引用格式（如 `[I@xxx`、`[Ljava.lang.xxx`）
  - 正文是纯 JSON 元数据片段（仅含 filename/size 字段，无实际内容文本）
- 一句话：正文能读出来且有一段有意义的内容才搬，几个字/一个数字/一堆括号不搬

## R9 格式清理（方案 B，v1）

> 老板开启方案 B 时生效。只对 markdown/html 生效，lake 永不清理（防 card 附件损坏）。

### 标题净化规则（搬入即执行）

按顺序执行，命中即处理：

0. **先 `title = title.strip()`**（必须最先做。语雀标题常带尾随空格，会让下面用 `$` 锚尾的正则**静默失效**）
1. 去重复后缀：`(重复标题-1)` / `（重复标题-2）` / `(重复标题-N)` 等，正则：`[（(]重复标题-\d+[)）]`
2. 去管道分隔来源尾巴（` | 卡卡罗特` / `｜xxx`），正则：`\s*[|｜][^|｜]*$`
3. 去字数注释 `（975 字）`，正则：`[（(]\d+\s*字[)）]`
4. 去末尾「空格-空格 + **来源词**」——**用白名单，不用形态正则**
   - 白名单：`博客园` / `卡卡罗特` / `老牛啊` / `南国微雪` / `LINUX DO`（转发新任务时按实际来源追加）
   - 正则：`\s+-\s+(博客园|卡卡罗特|老牛啊|南国微雪|LINUX DO)\s*$`，循环最多 2 次
5. 整体 trim + 连续空白压缩（`re.sub(r'[\t\n\r]+', ' ', ...)` + `re.sub(r'\s+', ' ', ...).strip()`）
6. **安全阀**：净化后 `len(净化后) < 3` → 跳过；**规则 2（管道）删掉的尾巴长度 ≥ 保留部分长度**（`A|B` 这类真标题风险）→ 不搬，标「拿不准（标题疑似被误净化）」列入报告
   - 规则 4 是白名单命中，属有意删除，**不计入安全阀**（避免 `XXX（重复标题-2）`→`XXX` 这类正确结果被误报）
7. 净化后标题为空或只剩 `-`/`|` → 不搬原文档，记入跳过清单（原因：R9 标题净化后为空）

⚠️ **血泪教训 A（2026-09-12 废弃19→废弃7 迁移）**：早期版本用 `\s*[-|]\s*[^（(]*$` 一刀切去末尾，导致 `黑马点评-点赞` → `黑马点评`、`02-NGINX常用配置` → `02`、`FunProxy - 使用 Rust...` → `FunProxy`，61 篇标题被截断 + 4 篇黑马去重撞车被误吞。**禁止用宽泛的 `-` 正则去末尾**。

⚠️ **血泪教训 B（2026-10-03 实测）**：换成「精确」形态正则 `\s+-\s+([^\s\-]+)$` 后**仍然误伤**——`2024 - 年度总结` → `2024`、`CUDA - 编程指南` → `CUDA`、`黑马点评 - 点赞` → `黑马点评`；且标题带尾随空格时它**一条都不删**（`Nginx 配置 - 老牛啊␠`）。**结论：`-` 分隔的副标题与来源后缀形态上不可分 → 一律改用来源词白名单（规则 4），不再用形态正则。**

### 去重规则

- 同标题多篇时保留一篇（优先 id 最小/内容最完整的那篇），其余跳过（原因：R9 重复）
- 目标库 B 已存在同标题文档 → 跳过（原因：R9 目标库已存在）

### 正文规范化规则（markdown/html）

1. 连续 3+ 空行压缩为 1 个空行
2. 行尾空白去除（`re.sub(r'[ \t]+$', '', line, flags=re.M)`）
3. 连续 3+ 个纯 `-`/`---` 分隔线行压缩为 1 个
4. 保留代码块、表格、图片、链接、标题层级原样不动
5. 不做内容改写（措辞/结构不动），只做空白/分隔符层面的清理

### 顺序

搬运时：get_doc → 判定（R1→R2→R8→R6→R5→R7→R3）→ **R9 标题净化+正文规范化（仅 markdown/html）** → create_doc/import_file 写入。

### 边界

- `format=lake` → 跳过 R9 全部处理，原样搬
- `format=html` → 标题净化照做，正文规范化只做空行/行尾/分隔线清理（HTML 标签不动）
- 清理动作在本地完成，不依赖语雀侧任何能力

## 拿不准处理

- R5 命中不了硬规则 → 打标"拿不准"，集中列一行给老板扫一眼，不搬
- 不猜，不自行扩大/缩小范围
